# 第 08 课：小项目实战——做一个你能演示的新功能

## 本课目标

在已有项目中完成一个“小而完整”的功能：有页面变化、有数据/逻辑、有验证和演示说明。

## 选题菜单

| 难度 | 选题 | 推荐练习点 |
| --- | --- | --- |
| 基础 | 资料完成度提示 | `computed`、条件渲染、样式 |
| 基础 | 个人主页欢迎语 | `v-if`、当前用户状态 |
| 中等 | 班级公告（只做前端演示） | 数组渲染、表单、组件 |
| 中等 | 用户修改密码 | 表单校验、PUT 接口、后端规则 |
| 挑战 | 班级公告（前后端完整） | 新路由、JSON 数据、管理员权限 |
| 挑战 | 照片墙点赞 | 用户关联、数组更新、重复点赞规则 |

## 开始前先写一页设计卡

在自己的作业文件中回答：

```text
功能名称：
谁能使用：
用户要完成什么：
页面要改哪个文件：
是否需要后端：
需要保存哪些数据：
成功时显示什么：
失败时提示什么：
如何测试：
```

## 推荐开发顺序

1. 先画出/写出页面文字和按钮，不接后端。
2. 加入前端数据和表单校验。
3. 若需要保存，再新增 API Service 和 Express 路由。
4. 用测试账号验证成功、失败和边界情况。
5. 写一段 60 秒演示词，并提交 Git。

## 禁止的捷径

- 不要只改前端显示或演示数据，就说“完成数据库功能”；应让 API、MySQL 结构、迁移和测试同时成立。
- 不要只做漂亮页面而没有可操作逻辑。
- 不要复制不理解的大段代码；每名学生要能说明自己改动的文件和数据流。

## 必做交付物

- [ ] 功能设计卡。
- [ ] 可运行代码。
- [ ] 至少 3 条测试记录：成功、错误输入、边界情况。
- [ ] Git 提交记录。
- [ ] 一张运行截图或 60 秒现场演示。
