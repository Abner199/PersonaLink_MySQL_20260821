# 第 07 课：业务规则——管理员、班级与照片墙

## 本课目标

理解“功能能做”之外，还需要“什么情况下允许做”。这类限制叫业务规则。

## 本项目的真实规则

| 规则 | 前端表现 | 后端处理 |
| --- | --- | --- |
| 注册必须选班级 | 下拉框必填 | 注册接口检查班级存在 |
| 班级有学生不能删除 | 管理页提示失败 | 删除路由计算成员数后拒绝 |
| 管理员可新增/删除用户 | 用户管理页按钮 | 管理员路由调用 `adminAuth` |
| 重置普通用户密码为 `123456` | 用户卡片按钮 | 重置接口拒绝管理员账号 |
| 管理员修改自己密码 | 用户管理页表单 | 验证当前密码并使旧会话失效 |
| 班级名单只管理员可查 | 班级管理页复制/导出 | 名单接口验证管理员令牌 |
| 普通用户照片墙看本班 | 页面隐藏班级筛选 | 页面按当前 `classId` 请求 |

## 跟着做

1. 用管理员创建一个空班级。
2. 在用户管理页新建一个用户，选择该班级。
3. 尝试删除该班级，观察失败提示。
4. 删除该普通用户后，再尝试删除班级。
5. 重置一个普通用户密码，用 `123456` 登录验证。

## 必做

- [ ] 完成一次“创建班级 -> 创建用户 -> 删除受阻 -> 清理成员 -> 删除班级”流程。
- [ ] 说出“页面禁用按钮”和“后端拒绝请求”的区别。
- [ ] 普通用户登录后检查照片墙只显示自己的班级。

## 安全边界

当前管理员管理接口已根据服务端随机临时令牌验证身份，但普通用户的所有接口还没有全面纳入 Session/JWT。课堂上可借此讨论：为什么后端最终应在每个私有接口验证“你是谁、你属于哪个班”。

## 挑战

设计“申请加入班级”功能：写出需要哪些页面字段、接口 URL、JSON 数据字段和审核规则；先交设计图，不要求立即写代码。
