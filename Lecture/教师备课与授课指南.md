# 教师备课与授课指南

> 教师可先用 [npm 命令词典与命名故事](./npm命令词典与命名故事.md) 统一学生的命令语言：强调 **ci = clean install**，**dev = development**，不要把命令当作需要死背的口令。

## 教学策略：先结果，后概念

对初学者，先让他们看到“我改一行代码，页面真的变了”，再解释组件、请求和数据。每节课遵循同一节奏：

```text
教师演示 10 分钟 -> 学生跟做 20 分钟 -> 独立完成必做 30 分钟
-> 同伴互测 15 分钟 -> 总结与 Git 提交 15 分钟
```

避免一开始讲完全部 HTML、CSS、JavaScript 语法。只讲本节任务必须用到的概念。

## 课前准备

1. 在教师电脑运行一次 `backend/npm ci`、`frontend/npm ci`。
2. 确认 `http://localhost:3000` 与 `http://localhost:3003` 都能打开。
3. 为每位学生准备独立工作目录、独立数据库或独立 Git 分支，避免多人互相污染演示数据。
4. 课前使用 `mysqldump` 备份教学数据库；需要重置时从可信备份恢复或重新执行 JSON 导入脚本。
5. 准备浏览器开发者工具：Elements、Console、Network 三个面板即可。

## 分层照顾

| 学生状态 | 课堂要求 |
| --- | --- |
| 起步学生 | 完成文档中的“必做”，能描述自己改了哪个文件 |
| 正常进度 | 完成必做并解释数据如何从页面到后端 |
| 进阶学生 | 选择挑战任务，写清测试步骤和 Git 提交说明 |

教师巡视时优先问：“你现在改的是页面、请求，还是数据？”让学生建立文件职责意识，而不是只帮其复制代码。

## 演示与故障教学

可刻意演示以下安全、可恢复的问题：

- 只启动前端：登录时出现网络错误，学生理解后端为什么必须启动。
- 注册重复邮箱：观察后端返回 400，理解规则不是只写在页面里。
- 删除仍有成员的班级：理解业务规则和数据关系。
- 在 Network 中查看登录请求：理解 URL、方法、请求体与响应。

不要让学生在真实公网或真实个人数据上练习；演示账号和 JSON 密码仅用于课堂。

## 每节课的验收口令

学生演示时必须说出四句话：

1. “我改的是哪个文件。”
2. “我改动后页面/接口发生了什么。”
3. “我如何验证它有效。”
4. “如果失败，我先看哪里。”

## 课堂结束收尾

要求学生完成：

```powershell
git status
git add .
git commit -m "learn: 完成第X课练习"
```

不会 Git 的学生至少截图保存已运行效果和关键代码；后续在第 09 课统一补齐版本管理。
