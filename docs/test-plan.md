# PersonaLink_MySQL 测试计划

## 环境准备

1. MySQL 已按 `backend/database/schema.sql` 建表并导入数据。
2. `backend/.env` 指向测试库，绝不指向唯一生产库。
3. 后端执行 `npm run db:verify`，前端执行 `npm run build`。

## 数据库与接口

- [ ] `GET /health` 返回 `status: ok` 和 `database: mysql`。
- [ ] 注册缺少班级、使用不存在班级、重复邮箱分别返回合理错误。
- [ ] 正常注册后，`users` 表出现用户且 `password_hash` 不是明文。
- [ ] 管理员创建用户、删除普通用户、重置普通用户密码为 `123456` 可用；不能重置/删除管理员。
- [ ] 管理员可用当前密码修改自己的密码；错误当前密码、少于 8 位、两次不一致均被拒绝。
- [ ] 修改管理员密码后新密码可登录、旧密码不可登录，当前页面可继续管理。
- [ ] 管理员能查看各班名单、复制姓名和导出 UTF-8 CSV；无令牌请求名单接口返回 401。
- [ ] 有学生的班级不能删除；空班级可删除。
- [ ] 搜索、同义词新建/编辑/删除、用户资料编辑均返回与页面预期相同的 JSON 结构。
- [ ] 普通用户照片墙只请求并展示本班成员；管理员页面的全量浏览行为保持原功能。

## 页面与移动端回归

- [ ] 登录、注册、资料编辑、班级管理、用户管理、搜索、照片墙均可进入。
- [ ] 390×844 或真实手机登录后可下滑到全部首页入口；“查看同学”可开关侧栏。
- [ ] 悬停照片卡片能放大，且白色装饰不遮挡照片细节。

## 迁移演练

- [ ] 从旧 JSON 执行 `npm run db:migrate-json` 后，班级、用户、同义词数量符合预期。
- [ ] 执行 `npm run db:verify` 通过，并记录班级、用户、学生、同义词、标准爱好、头像数量和头像字节数。
- [ ] 备份脚本生成非空 `.sql.gz`、`.sha256`、`.git-commit`、`.inventory.json`，`sha256sum -c` 全部显示 `OK` 且 `gzip -t` 通过。
- [ ] 把整组备份复制到另一台机器，从 MySQL 导入独立测试库后再次通过 `db:verify`。
- [ ] 新旧库的全部 `db:verify` 计数相同，管理员可登录，用户上传头像仍可显示，同一 Git commit 的默认图片可访问。
- [ ] 模拟旧服务器停止写入后生成最终备份，确认新站验收前旧、新后端不会同时接受写入。

## 发布判定

仅当构建、数据库校验、关键人工回归和备份恢复演练均通过，才可创建 Git Tag/Release。任何数据库结构或迁移脚本变化都必须在测试库先验证。
