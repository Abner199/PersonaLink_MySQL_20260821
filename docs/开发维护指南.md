# PersonaLink 开发维护指南

本文供以后修改代码、导入旧数据和发布版本时查阅。普通使用者只需阅读《软件使用说明书》，服务器管理员阅读《Ubuntu 24.04 部署与迁移教程》即可。

## 1. 项目结构

```text
frontend/                   Vue 3 + Vite 页面
  src/views/                页面
  src/stores/               Pinia 状态与业务调用
  src/utils/api/            Axios 请求封装
backend/                    Express + MySQL API
  routes/                   用户、班级、照片墙、同义词接口
  database/schema.sql       MySQL 表结构
  scripts/                  建表、旧数据导入、校验、创建管理员
scripts/                    Windows MySQL 备份与恢复
nginx.conf                 Ubuntu Nginx 模板
docs/                       操作文档与测试记录
Lecture/                    独立教学课程，不是部署说明
```

请求链路：

```text
Vue 页面 → Pinia Store → Axios → Express 路由 → mysql2 连接池 → MySQL
```

前端不能直接连接 MySQL。数据库密码只能放在后端服务器的 `backend/.env`。

## 2. 本地开发

需要 Node.js 20+、npm 和 MySQL 8.0+。先复制并填写配置：

```powershell
Copy-Item backend/.env.example backend/.env
```

首次准备测试库：

```powershell
Set-Location backend
npm ci
npm run db:schema
npm run db:migrate-json
npm run db:verify
```

`db:migrate-json` 会清空目标库业务表再导入 `db.json`，只能用于空库或明确允许覆盖的测试库。

分别启动：

```powershell
Set-Location backend
npm run dev
```

```powershell
Set-Location frontend
npm ci
npm run dev
```

浏览器打开 `http://localhost:3000`。

## 3. 从旧 `db.json` 导入 MySQL

1. 停止旧项目写入并复制 `backend/db.json` 原件。
2. 让 `backend/.env` 指向新库或测试库。
3. 先备份目标 MySQL。
4. 执行：

```powershell
$env:JSON_SOURCE = 'C:\备份\旧项目\backend\db.json'
$env:ADMIN_INITIAL_PASSWORD = '为旧管理员设置的临时密码'
npm run db:migrate-json
Remove-Item Env:JSON_SOURCE
Remove-Item Env:ADMIN_INITIAL_PASSWORD
npm run db:verify
```

导入内容包括班级、用户、资料、头像、同义词和标准兴趣词；用户密码会转为 bcrypt 哈希。`backend/db.json` 不是运行数据库，也不是日常增量同步工具。

## 4. 新数据库创建管理员

全新空库没有管理员，可在 `backend` 目录临时设置环境变量：

```powershell
$env:ADMIN_EMAIL = 'admin@system.com'
$env:ADMIN_NAME = '系统管理员'
$env:ADMIN_INITIAL_PASSWORD = '至少8位的临时强密码'
npm run db:create-admin
Remove-Item Env:ADMIN_EMAIL
Remove-Item Env:ADMIN_NAME
Remove-Item Env:ADMIN_INITIAL_PASSWORD
```

脚本不会覆盖已有邮箱。创建后应登录页面修改长期密码。

## 5. 数据与安全边界

- MySQL 保存班级、用户、资料、同义词及当前上传头像。
- 默认图片位于 `frontend/public/images`，随代码版本发布。
- 密码使用 bcrypt 哈希，SQL 使用参数化查询。
- 管理员接口使用服务端随机令牌，默认 8 小时失效，后端重启后需重新登录。
- 普通用户接口尚未全面实现 Session/JWT 权限隔离。面向大规模公网用户前，应补充全用户鉴权、限流、输入和上传校验、审计日志。
- `.env`、SQL 备份、`backend/db.json`、真实上传数据不得提交 Git。

## 6. 前端性能规则

- 动画优先使用 `transform` 和 `opacity`。
- 滚动动画统一使用 `useOptimizedAnimations().animateOnScroll()`。
- 组件卸载时断开观察器、事件和定时器。
- 用户开启“减少动画”后，内容仍必须可见。
- 开发环境按 `Ctrl+Shift+P` 可查看项目性能面板。
- 修改多个页面后，用浏览器 Performance 面板检查照片墙滚动和内存。

## 7. 修改后的最低检查

```powershell
Set-Location backend
npm run db:verify

Set-Location ../frontend
npm run build
```

然后按 [测试计划](./test-plan.md) 检查登录、注册、资料、班级、名单、CSV、用户管理、照片墙、搜索和同义词。

## 8. Git 与发布

代码和数据是两条版本线：Git Commit/Tag 保存代码，MySQL 备份保存实时数据。发布前两者都要准备。

```bash
git status
git add .
git commit -m "feat: describe the change"
git push origin main
git tag -a v1.0.0 -m "stable release"
git push origin v1.0.0
```

发布说明应记录：代码变化、数据库结构变化、是否需要迁移、测试结果和对应备份位置。不要用 `git reset --hard` 代替生产回滚；它不会恢复 MySQL，还可能删除未提交代码。
