# PersonaLink MySQL v1.0.2 发布说明

发布日期：2026-09-08  
发布级别：稳定补丁版  
兼容基线：`v1.0.1`  
数据库结构变更：无

## 版本目标

本版本把容易漏步骤的人工升级整理为同一套可审计发布流程。服务器已有的学生、班级、密码、资料和头像继续保存在 MySQL，CI/CD 不会用仓库模拟数据覆盖生产数据库。

## 新增功能

- 新增跨平台版本一致性检查，核对根目录、前后端 package 和 lockfile 共 7 处版本。
- 新增跨平台后端 JavaScript 语法检查。
- 新增数据库清单比较工具，保护班级、用户、学生、同义词、头像和管理员状态。
- 新增 Ubuntu 固定标签发布脚本，自动执行备份、构建、数据比对、重启和版本验收。
- 新增 GitHub Actions CI，在临时 MySQL 中完成完整集成检查。
- 新增手动生产 CD，支持 GitHub production Environment 审核、SSH Secrets 和部署互斥。
- 新增独立 CI/CD 文档，全部终端命令带注释且保持一行一条。

## 数据安全保证

生产发布脚本不会运行以下命令：

- `npm run db:migrate-json`
- `npm run db:schema`
- `DELETE`、`DROP` 或 `TRUNCATE`
- `docker compose down -v`

脚本在修改运行服务前调用 `/usr/local/sbin/backup-personalink`，保存 SQL gzip、SHA-256、Git commit 和数据库清单四件套。升级前后 11 项数据只要有一项变化，发布就会停止并提示人工核对。

## CI 检查范围

- Node.js 22 和 npm lockfile 安装。
- 版本号一致性和标签版本一致性。
- 17 个后端 JavaScript 文件语法。
- MySQL 8.4 临时数据库建表。
- 仓库模拟数据只读检查、临时库导入和完整性核验。
- Vue/Vite 生产构建和构建产物上传。

CI 中的数据库是每次运行新建的容器，与 `peaceinside.fun` 生产 MySQL 没有网络连接。

## 第一次升级到 v1.0.2

在 Ubuntu 服务器逐行执行：

```bash
# 进入项目并确认没有未提交文件。
cd /srv/personalink
git status --short

# 获取标签并从 v1.0.2 提取安全发布脚本。
git fetch --tags origin
git show v1.0.2:scripts/deploy-release.sh | sudo tee /usr/local/sbin/deploy-personalink-release > /dev/null
sudo chmod 700 /usr/local/sbin/deploy-personalink-release

# 自动备份并升级；不会覆盖 MySQL 学生数据。
sudo /usr/local/sbin/deploy-personalink-release v1.0.2
```

成功后应显示：

```text
发布成功：v1.0.2；MySQL 数据清单保持一致。
```

## 启用 GitHub CD

按 [CI/CD 发布与安全部署](../CI-CD发布与安全部署.md) 配置 production Environment、专用 SSH 用户和以下 Secrets：

- `PRODUCTION_HOST`
- `PRODUCTION_URL`
- `PRODUCTION_USER`
- `PRODUCTION_SSH_PRIVATE_KEY`
- `PRODUCTION_KNOWN_HOSTS`

配置完成后，在 GitHub Actions 页面手动输入 `v1.0.2`。CD 会先确认这是已经发布的 Release，再连接服务器执行固定脚本。

## 回滚

本版本没有数据库结构变化。需要回退代码时可调用同一脚本部署旧正式标签，脚本仍会先备份并核对数据：

```bash
# 回退代码到 v1.0.1，MySQL 数据保持当前状态。
sudo /usr/local/sbin/deploy-personalink-release v1.0.1
```

不要移动或覆盖任何已发布标签。修复本版本时应发布 `v1.0.3`。
